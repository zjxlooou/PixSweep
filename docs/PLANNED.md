# PixSweep 计划功能

> 本文档列出**计划改进**的方向与目标，供排期与验收。范围 = 评分准确度 + 性能/体验 + 发布/安装包（已确认**不含**任何前端人脸框/红点可视化）。已落地的改进见 `docs/FEATURES.md` §11。
> 每项含：问题 → 目标 → 用户价值 → 验收标准。详细技术实现见 `docs/PLANNED_TECH.md`。

---

## 一、评分准确度优化（核心卖点「人像优先」）

### A1. 修 eye ROI + 闭眼判罚聚合：让睁眼人像不再被误判为闭眼【已落地，见 FEATURES §11】
- **问题**：真图验证发现 OCEC 几乎对**每张人脸图都判"其中一只眼 prob_open = 0.00"**（实焦-正脸眼镜框入 ROI；宋宇芳、邹存 等大脸也单/双眼 0.00）。旧 `min(open)` 恒为 0 → 闭眼降权**对所有脸恒 ×0.5**，无区分度；睁眼人像被系统性低估。
- **真图 A/B 结论**：根因有二，分开修——① **采样**：`det_10g` 5 关键点被眼镜/旋转带偏 → 单眼 ROI 采到皮肤/眼镜 → OCEC 给 0.00；② **聚合**：`min(左,右)` 太脆弱，任一眼噪声 0.00 就压垮整张睁眼花。
- **已实施**：
  - **方案一（采样重锚定）**：`sample_eye_rgb_internal` 直接以检测到的眼关键点为中心、沿眼线方向采 24×40，替代 5 点模板投影；删除 `crop_eye_window`。救回"模板投影采偏"的眼（实焦-正脸 R 0→0.93、宋宇芳 L 0→1.00）。
  - **聚合改 `max`**（阶段三）：`eye_open = max(open_l, open_r)`，只有双眼都判闭才降权。`AI_FACE_CACHE_SCHEMA`=3，旧缓存失效。
- **验收（实测）**：竖屏-实焦-正脸综合 3.40→**6.79**、宋宇芳 3.41→**6.81**（睁眼不再被压）；竖屏-虚焦-侧脸保持 ~3.3（降权）；实焦>虚焦排序保留。**通过**。
- **遗留（可选后续）**：**眼镜/旋转鲁棒**——关键点本身被眼镜/旋转带偏时，再好的 ROI 采样也救不回（模型局限）。若需彻底，考虑"对齐（A2）后按固定模板位采样"或换更稳的闭眼模型。`min→max` 是为避免该局限压垮整脸而做的务实折中。

### A2. 全仿射对齐（`align_face`）【中优先级，需实证】
- **问题**：`align_face` 只用相似变换（平移+缩放+旋转，`estimateAffinePartial2D` 等价）从 5 关键点对齐人脸 crop；对侧脸/遮挡 crop 不够准，影响人脸专评与 eye ROI。
- **目标**：升级为完整仿射（含错切，6-DOF `estimateAffine2D` 等价）拟合 5 点，改善侧脸 crop。
- **风险**：spec 内部矛盾（它把"完整仿射"与 `estimateAffinePartial2D` 混为一谈，后者实为无错切的相似变换）；且直接改 `align_face`，对已调好的"实焦>虚焦"排序是**最高回归风险**改动。
- **验收**：实焦/虚焦、侧脸、戴眼镜三类真图上，改后**不劣化**实焦>虚焦排序；侧面 crop 更正。**劣化则弃**。

### A3. 场景权重数据校准【中优先级】
- **问题**：`composite_scores` 里人脸/风景/宠物权重是硬编码常量（0.20/0.20/0.45/0.15 等），未经真实照片集校准，"拍脑袋"。
- **目标**：用真实照片集标注"哪张更好"，线性回归/网格搜索校准各组权重，使推荐优先级符合直觉。
- **验收**：校准后，在标注集上"推荐即最好"的准确率明显提升；超参数与权重集中管理、可复现。

### A4. 关键点可信度（已落地）【已完，非计划】
已实现 `landmarks_trustworthy`（见 FEATURES §11）。仅拦明显退化，不误伤侧脸/遮挡/眼镜。

## 二、性能 / 体验优化

### P1. 人脸检测去重：一图只检一次【中优先级，纯性能】
- **问题**：扫描时每张有人脸的图，`face_scores`（人脸专评）与 `eye_open_probs`（闭眼）**各自检测一次** det_10g（engine.rs 671 行 + 517 行），同一图检测两遍，每遍 ~50ms。
- **目标**：一图只 det_10g 一次，结果（bbox + 5 关键点）在人脸专评 / 闭眼 / 场景之间复用。可顺带供 `get_face_landmarks`（若保留）复用。
- **验收**：大目录扫描耗时下降（尤其人像多时）；分数不变。
- **注意**：需把"检测 → crop → 评分"按图缓存中间结果（一次扫描内），或改为单遍流水线。

### P2. 扫描/评分流水线细分【低优先级】
- 现状：增量缓存已跳过"未变化文件"（哈希/尺寸/美学/技术/人脸/场景/闭眼）。剩余优化点：解码复用（人脸专评、闭眼、场景各自 `load_image_oriented` 解码三次）、并发控制。
- **目标**：每张图在一次扫描内解码一次、三次模型推理复用解码结果。
- **验收**：扫描耗时下降，分数不变。

### P3. 体验反馈【低优先级】
- 当前进度按 `ScanPhase`（扫描/哈希/聚类/评分）推送；可加更细的当前文件/阶段内进度。若用户需要再排。

## 三、发布 / 安装包修复

### R1. 打包白名单补全人像/场景/闭眼模型【低风险, 当前打包有 bug】
- **问题**：`build_release.ps1` 的 `$neededModels` 只列了基础评分模型，**漏了** `insightface/`、`scene/`、`eye/` 子目录（det_10g/mobilenet_v3/ocec 等）。→ 当前发布的 zip 里人像评分/闭眼/场景功能是**空转**的（模型缺失仅 warn 跳过）。
- **目标**：`$neededModels` 显式列入子目录模型 + 配对 `.data` 文件。
- **验收**：解压发布包后跑人像组扫描，日志出现"InsightFace/OCEC/场景 就绪"，不再"跳过"。

> 说明：CUDA / DirectML 引擎分包（原 R1）**不做**——相比功能完整，安装包大小不重要；单一发行包同时带两套引擎回退链更稳妥。

---

## 四、顺序与依赖建议

1. **R1**（打包白名单补全人像模型，低风险，先修，否则分发出去的人像功能是坏的）。
2. **A1**（eye ROI，最高价值；它决定"准确度优化"是否真的有效——A2/A3 都建立在眼睛判定可靠之上）。
3. **P1**（人脸检测去重，纯性能，独立于 A1，可并行）。
4. **A2**（全仿射，高回归风险，需在 A1 基础上实证；劣化即弃）。
5. **A3**（场景权重数据校准，可在准确度稳定后推进）。
